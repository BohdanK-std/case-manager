# Task Manager

## Предметна область

**Управління завданнями** — організація, планування та контроль виконання завдань користувачами.

## Призначення проєкту

**Task Manager** — вебзастосунок, призначений для спрощення процесу підбору, організації та виконання завдань. Користувач зможе створювати проєкти та завдання, розподіляти завдання за категоріями, встановлювати терміни виконання та відстежувати їхній стан.

## Передбачувані сутності даних

Основними сутностями даних у проєкті передбачається зробити:

* **User** — користувач системи, який створює та керує проєктами й завданнями.
* **Project** — проєкт, що об’єднує пов’язані між собою завдання.
* **Task** — окреме завдання, яке належить до певного проєкту та може мати назву, опис, категорію, термін виконання та статус.
* **Category** — категорія для групування та впорядкування завдань.

У процесі розробки перелік сутностей може бути розширений відповідно до функціональних вимог проєкту.

## План розвитку проєкту

Розробка вебзастосунку буде виконуватися поетапно відповідно до тем курсу.

### 1. Створення базової сторінки та підготовка проєкту

Створення репозиторію проєкту та базової вебсторінки `index.html`. Ознайомлення з принципами роботи вебу: HTTP-запитами та відповідями сервера, DNS, TLS, статус-кодами та процесом рендерингу сторінки. Використання DevTools для перевірки роботи вебсторінки.

### 2. Створення структури інтерфейсу

Розробка HTML-структури вебзастосунку з використанням семантичних елементів. Створення основних сторінок та елементів інтерфейсу для роботи з проєктами й завданнями. Додавання форм для створення та редагування даних, валідації введення та метаданих. Забезпечення базової доступності інтерфейсу.

### 3. Оформлення інтерфейсу за допомогою CSS

Додавання CSS та оформлення створених HTML-елементів. Використання каскаду, специфічності та блокової моделі. Побудова основної структури сторінок за допомогою **Flexbox** і **Grid**.

### 4. Адаптивність та дизайн-система

Покращення візуального оформлення вебзастосунку та створення єдиного стилю інтерфейсу. Налаштування кольорової палітри, типографіки та відступів. Додавання адаптивності за допомогою медіазапитів, забезпечення достатнього контрасту та підтримки темної теми.

### 5. Додавання JavaScript

Додавання JavaScript для реалізації інтерактивної поведінки вебзастосунку. Робота з DOM та подіями, створення, редагування та видалення елементів інтерфейсу без необхідності повного перезавантаження сторінки. Використання `Promise`, `async/await` та `fetch` для роботи з даними.

### 6. Перехід на TypeScript та сучасний інструментарій

Перехід від JavaScript до TypeScript для покращення типізації та структури коду. Використання інтерфейсів та інших можливостей TypeScript. Налаштування інструментів розробки, зокрема Vite та ESLint. Подальше використання Git для контролю версій та організації розробки.

### 7. Розробка клієнтської частини за допомогою React

Перехід до компонентної структури React. Поділ інтерфейсу на окремі компоненти та використання `props` і стану. Робота зі станом за допомогою `useState`, виконання побічних ефектів через `useEffect`. Реалізація маршрутизації між основними сторінками вебзастосунку.

### 8. Створення серверної частини

Розробка серверної частини за допомогою **Node.js та Express**. Створення REST API для роботи з користувачами, проєктами, завданнями та категоріями. Реалізація маршрутів та middleware, обробка HTTP-запитів і повернення відповідних статус-кодів.

### 9. Підключення бази даних

Проєктування структури бази даних та зв’язків між сутностями **User, Project, Task і Category**. Реалізація операцій CRUD для створення, отримання, редагування та видалення даних. Використання SQL-запитів та індексів. Забезпечення захисту від SQL-ін'єкцій.

### 10. Безпека та розгортання вебзастосунку

Реалізація авторизації користувачів та захисту їхніх даних. Захист від основних вебзагроз, зокрема XSS і CSRF, налаштування CORS та роботи з токенами. Оптимізація продуктивності, кешування та зменшення розміру клієнтського бандла. Підготовка вебзастосунку до розгортання та налаштування CI.

## Запуск проєкту

На поточному етапі проєкт містить базову HTML-сторінку, тому для перегляду достатньо відкрити файл `index.html` у браузері.

На наступних етапах проєкт буде доповнений стилями, клієнтською та серверною частинами, базою даних, авторизацією та іншими функціональними можливостями.
